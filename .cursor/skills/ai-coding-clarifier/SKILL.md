# ai-coding-clarifier

文件读写权限与存储路径 → 见 **ai-coding-file-conventions skill**。
通用约束（文件合规/歧义处理/返回格式）→ 见 **ai-coding-sub-agent rule**。

## 使用场景

用户需求口语化、存在歧义、边界不清时，通过多轮提问将需求固化为当前有效需求陈述（`Final.md`），同时保留每轮原始对话增量（`V<n>.md`）供追溯。

**禁止**：读任何业务代码——读了会被既有实现带偏。

**自检**：有没有打开或读取任何 `src/` 下的文件？有 → 立即停止，只看用户原始输入。

---

## 输入

- 用户原始需求原文
- 业务名（修订时传入；首次不传，自行提议）；路径见 **ai-coding-file-conventions skill**

**自检**：追加模式下是否有业务名？没有 → 向调用方请求，不自行假设或新建。

---

## 执行流程

1. **多轮澄清**：逐轮用 `AskQuestion` 提问（每轮 1~3 个问题，每个问题给候选答案，不让用户自由回答）；循环直到无新歧义浮现
   → **验证**：每个问题都有候选选项，没有开放式输入框。

2. **归纳摘要**：整理 3~5 条候选总结（每条 ≤ 50 字，结构「动词 + 对象 + 关键约束」）；提议业务名（英文短词或拼音，全小写 + 连字符，如 `order-export`）
   → **验证**：总结 3~5 条；业务名无中文 / 空格 / 特殊符号。

3. **用户确认**：`AskQuestion` 展示 3~5 条候选 + 业务名，让用户选「确认归档 / 继续澄清」
   - 继续澄清 → 回到步骤 1
   - 确认归档 → 进入步骤 4
   → **验证**：用户明确选了"确认归档"，clarifier 不自行判定"差不多了"。

4. **归档**：
   - 写 `V<n>.md`（n = 现有最大编号 + 1；首次 n = 1）：只记录**本轮对话原文**（格式见下方）
   - 覆盖写 `Final.md`：整合上一版 `Final.md`（首次为空）+ 本轮用户表达，重写为当前有效需求（贴近用户原文，不含对话往返和 AI 说明）
   → **验证**：V<n>.md 只有 `user：` / `ai：` 行，无 AI 思考段落、无前版内容；Final.md 只有需求陈述，无对话往返。

**追加澄清**（业务名已存在时）：
- 必读上一版 `Final.md` 作为本轮起点上下文（仅供 clarifier 理解当前状态，不写入 V 文件）
- 本轮澄清在上一版基础上追加、修改或否定部分需求
- 写 `V<n+1>.md`：只记录**本轮对话原文**，不含前版 Final.md
- 覆盖写 `Final.md`：将上一版 + 本轮变更合并为新的当前有效需求陈述

**自检**：步骤 4 归档前，V<n>.md 里是否混入了 AI 思考过程或前版 Final.md 内容？有 → 清除后再写入。

---

## 输出

输出：业务名（调用方据此派生所有标准路径，无需 clarifier 回传绝对路径）

**自检**：返回值里有没有绝对路径或文件内容？有 → 删除，只报业务名。

---

## Final.md 内容结构

记录**当前有效需求**，贴近用户原文，不含对话往返、AI 说明或 AI 归纳结论。每次归档覆盖写入，不保留历史版本。

```
<贴近用户原文的当前需求陈述，可多段>
```

示例（经两轮澄清后）：
```
我需要查询出 B 和 C 的数据，按时间倒序排列，支持分页。
```

**自检**：Final.md 里有没有 `user：` / `ai：` / `问：` / `答：` 这类对话格式？有 → 删除，只保留需求陈述原文。

---

## V<n>.md 内容结构

只记录**本轮对话原文**，不含任何前版内容，不累积历史。

**严格规则**：
- 只记录用户看到的和用户输出的：`user：<原文>` 和 `ai：<结论原文>`
- **禁止**写入 AI 内部思考过程（`<thinking>` 块、推理段落、分析展开）
- **禁止**写入前版 `Final.md` 内容

```
user：<原文>
ai：<原文>
user：<原文>
...
```

> AI 理解有疑问时，将 V1.md + V2.md + ... 全部拼接即可还原用户完整澄清过程。

**自检**：V<n>.md 每行是否都以 `user：` 或 `ai：` 开头？有其他内容 → 删除。AI 行是否只有结论，没有推导过程？有推导 → 只保留最终结论行。

---

## 完成标准

- `Final.md` 写入 chatHistory 目录下（路径见 **ai-coding-file-conventions skill**），只含需求陈述，无对话往返、无 AI 分析
- `V<n>.md` 写入 chatHistory 目录下，只含本轮 `user：` / `ai：` 行，无 AI 思考过程、无前版内容
- 业务名为合法路径片段（全小写 + 连字符，无中文 / 空格）
- 输出时只报业务名

---

## 生效信号

- 每轮 `AskQuestion` 都有候选选项，没有开放式问题
- `V<n>.md` 只有 `user：` / `ai：` 行，用记事本打开看不到任何其他格式内容
- `Final.md` 是一段纯需求陈述，看不到任何 `user：` / `ai：` 字样
- 将所有 `V<n>.md` 拼接后能还原完整对话，不依赖 `Final.md`
- 输出只有业务名字符串
