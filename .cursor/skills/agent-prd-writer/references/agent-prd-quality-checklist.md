# Agent PRD 质量自查清单

> 在把初稿交给用户 / 评审会之前，对照此清单逐条检查。任何一条"否"，优先回去补齐。

## A. 基础完整性（Must-have）

- [ ] 一句话产品定义能回答"给谁 / 在什么场景 / 做什么 / 带来什么价值"
- [ ] 至少 3 个真实的核心场景故事（User Story），每个都附具体对话示例
- [ ] 核心任务不少于 3 个，每个任务按模板写齐 6 个子节（描述、流程、输入、输出、依赖、验收）
- [ ] 所有 P0 任务都有可量化的验收标准（不是"准确率高"而是"≥ 85%"）
- [ ] MVP 范围在"里程碑"章节里有显式表格，哪些做、哪些不做一目了然

## B. Agent 专属维度（重中之重）

- [ ] 能力边界章节明确列出 In-scope / Out-of-scope / Edge cases
- [ ] 每个工具 / 插件在 Tool Catalog 里都有 name、description、入出参、是否幂等、是否需审批
- [ ] 评测方案有明确的数据集来源、指标清单、上线门槛
- [ ] 失败 & 幻觉章节覆盖至少 5 种失败模式和对应兜底
- [ ] 模型行为契约给出至少 3 组 Good/Bad 对比示例
- [ ] 成本章节对每个核心任务给出 token 估算和单次成本估算
- [ ] 延迟预算覆盖端到端 P95 和各环节拆解
- [ ] 合规章节回答了数据是否被用于训练、PII 如何处理、是否需要备案

## C. 写作质量

- [ ] 所有章节都有实质内容，没有"待补充 / TBD / ⏳"挂着不填
- [ ] 所有"待确认"项都用统一格式 `> ⚠️ 待确认：……` 标注
- [ ] 每个 blockquote 里的设计决策都说了"为什么"而不只是"是什么"
- [ ] 表格列宽合理，列数 ≤ 6 避免在飞书文档溢出
- [ ] 示例对话 ≥ 5 组，语气统一、情景真实，不是"你好"、"再见"式的空示例
- [ ] 没有"我们会 / 我们将 / 未来"这类虚指，改成 "MVP / v1.1 / v2.0" 明确版本承诺

## D. 可落地性（评审会过关）

- [ ] 研发读完能拆出具体的 JIRA story，不需要回来再问
- [ ] 算法读完能直接开始做评测集建设
- [ ] 法务读完能判断是否需要补评估、要评估什么
- [ ] 数据团队读完能把指标落到看板
- [ ] 运营读完知道自己要准备什么知识 / 话术 / 标注

## E. 反模式（Anti-patterns）自查

- [ ] ❌ 没有把 "AI" 当万能药，即"这里有个难点，让 AI 来解决"这种空话
- [ ] ❌ 没有把 Agent 当传统 Chatbot，即只写"用户输入 → Agent 回复"而忽略工具调用与自主决策
- [ ] ❌ 没有忘记"AI 生成内容标识"等合规要求
- [ ] ❌ 没有 over-promise，即 MVP 承诺了 L4 自主度但评测门槛只写了 70%
- [ ] ❌ 没有把"成本和延迟"留到技术评审才讨论
- [ ] ❌ 没有把多轮对话当单轮对话写（多轮的状态、记忆、纠错是最容易被忽略的）

## F. 交付前最后一步

- [ ] 在文档开头或结尾列出 3-5 个**最关键的待确认项**
- [ ] 标注 1-2 个**我（PM / 文档作者）已经拍板的关键决策**及理由，邀请评审方确认或推翻
- [ ] 关联文档链接补齐（TDD、评测方案、用研、竞品）
- [ ] 版本号从 v0.1 升到对应阶段（草稿 → 评审 → 修订）
